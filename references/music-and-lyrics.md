# 找音乐和歌词

项目需要两个文件，都放在 `assets/` 里：

- `song.mp3`：也可以是 `song.m4a` / `song.wav` / `song.flac`
- `song.lrc`：带时间轴的歌词

## 目录
1. 用户自己提供
2. 从 music.tom.moe 搜索下载
3. 只有纯文本歌词时怎么做 LRC
4. 检查歌词时间轴对不对
5. 版权提醒

---

## 1. 用户自己提供

用户有自己的歌（原创、翻唱、demo、本地收藏）时，直接请对方发来：

> 把音乐文件（mp3 / m4a / wav / flac 都行）和歌词发给我。歌词最好是 .lrc 格式，网易云、QQ 音乐都能导出；只有文字也可以，我来对时间轴。

收到后：
- 统一重命名放进 `assets/`。格式不是 mp3 也不用转，引擎都认。
- 用 `ffprobe -v error -show_entries format=duration -of csv=p=0 assets/song.mp3` 看一下时长，确认文件能读。
- 打开 LRC 看格式：每行是 `[分:秒.百分秒]歌词`。开头可能有 `[ti:歌名]`、`[ar:歌手]` 这类信息行，片头片尾标题就从这里取。
- LRC 里“作词：xx”“编曲：xx”这类带冒号的行，引擎会当作制作人员名单，不当歌词显示（片尾可以拿来滚字幕）。第一行如果是“歌名 - 歌手”，也会自动跳过。
- 文件编码要是 UTF-8。打开是乱码，多半是 GBK，用 node 转一下：`iconv-lite` 或 `TextDecoder('gbk')`。

## 2. 从 music.tom.moe 搜索下载

用户只给了歌名时用这个网站。它是个多平台搜索站，能直接拿到音频地址和 LRC 地址。

**下载任何文件之前，先把文件名、来源、大小告诉用户，等用户同意。**

### 用浏览器工具（推荐）

1. 打开 `https://music.tom.moe/`。
2. 搜索框（占位文字是“例如: 不要说话 陈奕迅”）里输入 `歌名 歌手`，下面选一个音乐源，回车搜索。
   - 网易源经常搜不到有版权的歌（会提示“没有找到相关信息”），先试 **QQ**，再试酷狗或酷我。
   - 网址参数 `?name=xx&type=qq` 有时会被页面重置回网易，最稳的是在页面上点选音乐源。
   - 歌名太长搜不到的话，只搜歌名。
3. 搜索结果是一个列表，第一首会自动选中。注意别选成 Live 版、翻唱版或伴奏，点列表里的歌可以切换版本。
4. 用 JavaScript 读页面里的几个隐藏输入框：
   ```js
   ['#j-name','#j-author','#j-src','#j-lrc','#j-link'].map(s => document.querySelector(s)?.value)
   ```
   `#j-src` 是音频地址，`#j-lrc` 是歌词地址，都是 `https://music.tom.moe/api.php?get=...&sign=...&t=...` 这种带签名的链接。签名会过期，拿到后要尽快下载。
5. 查音频大小（这个地址会 302 跳转到平台的 CDN）：
   ```bash
   curl -sIL "<j-src 的地址>"     # 看最后一个 Content-Length
   ```
6. 告诉用户，等确认：“找到了《xx》（歌手，QQ 源，原版）。准备下载 song.mp3 约 12.6MB（来自 xx 音乐 CDN）和 song.lrc 歌词文件，可以吗？”
7. 用户同意后下载：
   ```bash
   curl -sL -o assets/song.mp3 "<j-src>"
   curl -sL -o assets/song.lrc "<j-lrc>"
   ```
8. 检查：mp3 有几 MB 而不是几 KB，`ffprobe` 能读出时长；LRC 里有时间戳。

### 没有浏览器工具时

请用户自己操作：打开 music.tom.moe，搜到歌后点结果下面的“音乐地址”和“歌词”按钮分别下载，再把两个文件发过来。

### 搜不到或下载失败

试其他音乐源、换个关键词，还不行就请用户自己提供文件（见第 1 节）。

## 3. 只有纯文本歌词时怎么做 LRC

LRC 的时间点决定了画面什么时候演到哪句，所以要尽量准。按推荐程度：

1. **找现成的。** 用 music.tom.moe 或各音乐平台搜同一首歌，常常能直接拿到 LRC。
2. **请用户标时间。** 用户最清楚自己的歌。可以请对方报每句开始的大概秒数，比如“第一句 0:28，第二句 0:31……”。
3. **自己估一个草稿，再请用户校对。**
   - 用引擎里的 `audioEnergy()`（或 ffmpeg 的 `silencedetect`）找出人声段落：前奏、间奏一般是能量较平的长段。
   - 把歌词按段落（主歌、副歌）分配到各个人声段里，段内按每句的字数比例分配时间。
   - 写成 LRC 草稿，渲染一段只有背景加字幕的测试片（起步模板就行），请用户边听边看，告诉你哪句早了、哪句晚了，再调整。

LRC 格式示例：
```
[ti:歌名]
[ar:歌手]
[00:28.36]第一句歌词
[00:31.14]第二句歌词
[00:40.12]
```
空行（只有时间戳）表示上一句到这里结束。一句歌词会一直显示到下一个时间戳为止，所以间奏前最好加一个空行。

## 4. 检查歌词时间轴对不对

- 整体都偏早或都偏晚：在 LRC 里加 `[offset:+300]`（单位毫秒，正数表示歌词提前），引擎会自动处理。
- 个别句子不准：直接改那一行的时间。
- 验证方法：`node engine/mv.js --from 25 --to 45 --out out/lyric_check.mp4` 渲一小段，自己用 ffmpeg 抽帧，看字幕出现的时间点；拿不准时请用户听一下。

## 5. 版权提醒

下载的歌曲版权属于原作者和平台。做好的视频适合自己收藏、送人；要公开发布（B 站、抖音等），要提醒用户注意音乐版权。另外，聊天里不要大段复述歌词，引用时只说时间点或几个字。
